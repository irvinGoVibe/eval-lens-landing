- 17:14 — fixed: **[P0] Второй экран главной больше не зависает и корректно проходит sticky → scrub → release на iPhone Safari.**
  - Route: `/`, component: `Problem`, selectors: `.scrub-track`, `.scrub-pin`, `.scrub-heading`, `.scrub-video`.
  - Root cause 1: mobile Safari вычислял legacy `100vh` как large viewport `874px` при visual viewport `660px`; sticky-сцена была выше видимого экрана и неверно фиксировалась/освобождалась.
  - Root cause 2: scroll loop записывал `video.currentTime` с порогом `1/120s`, включая новые random-access seeks до завершения предыдущего seek. На H.264 `1600×900`, 15 fps это блокировало WebKit main thread.
  - Fix: на iPhone track/pin используют стабильные `320svh`/`100svh`; video scrub квантован к фактическим 15 fps и отправляет только один seek за раз, продолжая после `seeked`; reduced-motion scene больше не перезаписывает одинаковые стили на каждом scroll tick.
  - Regression: `homepage mobile scrub pins, advances, and releases` — Mobile Chromium + Mobile WebKit passed.
  - Physical Safari: iPhone 16 Pro, Safari 26.5, viewport `402×660`; pin height `660`; video `0 → 1.867 → 5.199s`; `videoSeeking: false`; heading state `shown → shown → hidden`; WebDriver commands no longer time out.
  - После проверки automation отключена, чтобы пользователь мог управлять Safari вручную.
